# Staged native raw printer

Dana's native console accepts `printer attach on`, `printer status`, `printer save /absolute/unique.raw`, `printer clear` and `printer attach off`. The desktop socket accepts command `printer` with the same action and argument text. `printer begin`, `printer abort` and `printer finish PATH` still work (finish is the same as save). Printer availability stays false. The Dana device profile has a separate `usbPrinter` capability (`usb_printer` in `tools/device-profiles.json`); its `usb` capability (USB HotSync) stays false. The HC level interrupt uses IRQ3/PD6, inferred from Dana firmware; the board net has not been measured.

While the printer is attached a job is always collecting, so frontends never send begin. It starts on `attach on` and starts again after save, clear, a bus or HC reset, the guest changing configuration or interface, a load and a port loss. `save PATH` publishes the collected bytes and then starts a new job. `clear` drops the collected bytes and starts a new job; the printer stays configured. `abort` cancels like a reset (the guest has to enumerate again). Nothing finishes by itself: packet ends, idle and disconnect do not save.

`printer status` answers `attached|off STATE bytes=N last=LAST idle=MS`. STATE is the job state (`collecting` while attached), N the bytes collected, LAST the result of the last save since attach (`none`, `published`, `rejected`, `uncertain`, `overflow`, ...) and MS the milliseconds since the last byte of this job arrived, or -1 when it has none. A frontend shows "print received" once bytes is above 0 and idle has passed a few seconds. `save` and `clear` answer `printer: ` then any error text and the same status. `save` fails when nothing is attached or the job isn't collecting (after an overflow, send `clear`).

Reset, port loss, detach, successful controller load, bank teardown and shutdown cancel collecting work. Invalid controller loads preserve live work. A runner load refused during early preflight retains work. Once replacement tears down banks it may cancel work even if loading fails and the previous core is rebuilt. No spool rollback is promised. The runner restores the attachment after rebuilding. After a direct controller load or machine hardware reset, use attach on again. HC software reset cancels the job and keeps the printer attached, collecting a new one. Attach again if needed; saved checkpoints contain neither spool nor publication history and cannot resume collecting work or automatically replay output.

Finish consumes the spool on success or failure. Write, file flush, close and publication errors are reported. Publication uses a private random staging name and an atomic no-overwrite hard link in the destination directory. Parent-directory flush failure after publication returns uncertain and retains the complete destination. Failed staging cleanup also returns uncertain and reports the retained staging path. If nothing was published and the staging file was removed but the directory flush failed, the result is rejected and the error names the staging path, which may reappear after a crash. Do not automatically retry an uncertain result. A crash before publication may leave a private staging file; a crash after publication may leave a complete destination with uncertain durability. Inspect it before deciding what to submit again. This is no persistent ledger or exactly-once guarantee across restart or arbitrary guest resubmission. A unique destination blocks overwriting that path, it does not recognise equivalent jobs submitted under another name.

One bounded Dana PrintBoy TestPage job returned to its test screen and published its accepted USB bytes through explicit finish. That stream contained plain text, CRLF lines and a final form feed, without escape sequences. This does not establish a general printer language, rendering, PDF, a physical printer or completion for other jobs. Infrared printing and Wi-Fi remain separate.

For Dana ROM 1.5 (SHA256 `329fe6674122109308aedb7953b967a9ac3fbd96d3e016f61e0f03cc6edff8a5`), `launch PBShell` opens PrintBoy. Choose Printer Setup, then Use Wizard to select a manufacturer and model. AlphaWord's database name is `WordSmith` (creator `WrdS`); PrintBoy's shell is `PBShell` (`BPSH`) and its configuration database is `BPMConfig` (`BCFG`). `db-list` lists RAM databases and does not establish whether these ROM applications are present. This setup route alone does not qualify a USB profile or a print job.

In that ROM, the wizard lists Epson C60 but selecting it reports that the Epson C60 driver is not installed. The model list does not establish installed driver availability. The ROM includes the separate `BPMEpson` driver; it does not include a `BPMEpsonC60` database. One bounded Generic (6.0) USB job completed, the TestPage job above; other profiles and general device acceptance remain unqualified. Dana's manual specifies selecting the printer, setting it as default, opening Edit, choosing USB under Port and tapping OK to save the port.

Host root changes latch RHSC in HcInterruptStatus. Acknowledging RHSC leaves the port's CSC and PRSC flags set until their own W1C writes. The microprocessor OPR latch needs its own acknowledgement after enabled HC causes are cleared. Later connection, power and reset events can raise RHSC while older port flags remain set. Saved controllers keep these existing latches; loading detaches external targets and records that new change. No saved-state version change is needed.

For a private, single-job packet trace, `python3 tools/check-usb-printer-capture.py trace.log job.raw` compares the raw file with ACK-accepted EP1 OUT payloads, suppressing repeated toggles. It requires one observed begin, an initial DATA0 bulk toggle and no reset, reconfiguration or second job in that interval. Keep the trace and raw file outside source control. The checker does not establish guest completion; inspect the returned TestPage and stream framing before issuing explicit finish. Run its synthetic checks with `python3 tests/usb-printer-capture.py`.
