# Raw print jobs

`src/common/RawPrintJob.h` owns one bounded raw byte stream, independent of USB or infrared. It is header-only and has no platform dependencies. `make test-raw-print-job` builds its focused test against an isolated reconstruction.

One owner uses it on one thread. Copying is disabled. Choose the byte limit at construction, call `begin`, append packet payloads, then call `finish` with a synchronous output callback or `abort`. Append copies the whole chunk or fails the whole job. Overflow, invalid nonempty input and allocation failure discard the buffered prefix and prohibit publication. Zero-length append is valid, including with a null pointer. A zero limit permits an empty job. The buffer retains capacity for reuse, bounded by the chosen limit in logical bytes; allocator overhead and vector capacity are not a process-memory quota. Destruction discards unfinished bytes without output.

The callback borrows the byte span only for the duration of the call, including a possible empty span. It must copy anything it retains. The context is borrowed, never deleted. The callback owns destination creation, permissions, write/flush/close errors and publication. It returns `published` only after its complete publication contract succeeds, `rejected` only when no output escaped, and `uncertain` when partial bytes or an output with uncertain durability escaped. Exceptions become `uncertain`. No file writer, path naming, rendering or destination selection is provided here.

Finish calls the callback once and discards the buffer on every result. Failed and uncertain outputs are terminal, with no automatic retry. Repeated finish returns the terminal state. Begin explicitly starts a new job after a terminal state; the caller must retain any error before doing so. During publication all mutators refuse re-entry. The owner and callback context must remain alive through finish. Abort applies only while collecting and never deletes an already published output. Invalid operations leave state unchanged.

USB and future IR adapters must decide job boundaries using established protocol or explicit host action. Packet boundaries, empty packets, disconnects and idle periods are not implicitly job completion. Reset, detach, load or shutdown must abort an incomplete job unless a separately specified policy says otherwise. Preserve all raw bytes, including binary zeros. Do not infer printer language, page count or PDF support. Printer capability stays unavailable until its transport and guest behaviour are qualified.

The backend has no savestate API. External output cannot rewind with guest state. Adapters must discard collecting work at a load boundary and must not replay completed output from a checkpoint. Any future external-output ledger must live outside rewindable machine state; this milestone supplies no exactly-once policy across process restart or load. Output errors require a host-visible result when wired into a frontend. Raw streams and outputs remain private evidence, never repository fixtures.

# Dana host continuation

H1 inspected `EmRegsISPDana::{Read,Write,Commit,Tick,StateFields,Load,RefreshIrq}` at 0472. Host command/data occupy base+2/base; device command/data occupy base+6/base+4. HC reads are whitelisted registers with split 32-bit accesses, and writes model reset, interrupt masks, frame interval, disconnected root ports and buffer-length allocation. Tick advances frame counters in operational state. There is no HC transfer-counter/ATL streaming implementation or PTD executor. `RefreshIrq` currently drives the device-controller path. Device-side `HostOut`, `HostIn` and ACK helpers serve the computer bridge, they are not a USB host controller. No HC code changes in H1.

Use the [Philips ISP1161A rev.03 datasheet](https://media.digikey.com/pdf/Data%20Sheets/NXP%20PDFs/ISP1161A.pdf), especially section 9.4 PTD organization and the HC register descriptions, to implement the next steps. PTD headers and payload/reserved IN space share buffer RAM; ATL and ITL both use PTDs. Do not substitute a generic OHCI memory descriptor walker for this chip's programmed buffer interface.

Derive command widths, alignment, count consumption, last-descriptor and completion fields from rev.03 before coding. Reject malformed/truncated descriptors and out-of-allocation transfers, with no partial machine mutation. Preserve device-controller behaviour and qualify save/load of partial host PIO accesses. Focused firmware-free tests should cover split accesses, allocation boundaries, odd/truncated transfers, chained PTDs, reset and late-invalid-load rollback. ## H2a ATL interface

0474 uses Philips ISP1161A rev.03 (23 December 2004), tables 4–5, sections 9.3, 9.4.2–3, 10.4.3 and 10.6.1–7. Commands 22/A2 hold a 16-bit byte count, 41/C1 stream 16-bit ATL words with the low byte at the even address. Each word advances two bytes. Count completion sets AllEOTInterrupt (bit 2) and write completion marks ATL full (bit 2), without claiming USB completion or ATL done. PTDs have eight-byte headers and four-byte aligned successors after TotalBytes of payload or reserved IN space. Last terminates the list. Completion updates actual bytes, toggle and completion code and clears Active.

Odd byte counts consume a final whole bus word; the unused high byte is zero on read and ignored on write. Rev.03 describes word accesses and byte counts without explicitly specifying the unused lane; this is a bounded model policy requiring guest qualification. The final physical word must fit the allocation. The counter register retains the programmed count. No implicit descriptor parsing occurs on PIO writes: partial and malformed guest prefixes remain representable. ValidateHostList checks a completed list without mutation. Decode rejects reserved fields, ISO format in ATL, reserved PID and completion codes 10/11, zero packet size, truncated payload and actual bytes beyond total. It preserves caller output on failure. Completion checks before changing the two result bytes. Trailing bytes may only be final alignment padding.

State version 6 appends fixed 4096-byte RAM and a bounded even cursor. Versions 2–5 load with empty host RAM/cursor. Invalid or truncated loads restore both controller paths. Software HC reset keeps RAM, clears allocation and cursor; hardware reset clears RAM too. No host execution, root attachment, IRQ routing or print output is supplied here.
